# 提示词分层：人格提示词与仿真提示词

QQ 机器人的提示词分两层：**人格提示词**决定「机器人是谁、怎么说话」，**仿真提示词**决定「机器人怎么在 QQ 里运转」。两层分工不清时，模型会同时收到互相矛盾的要求（例如人格要求展开讲，仿真层又要求「一般 3~5 句」），表现就不稳定。

本文说明两层各写什么、各起什么作用，以及改动时要注意什么。

## 0. 总览

| | 人格提示词 | 仿真提示词 |
| --- | --- | --- |
| 回答的问题 | 你是谁、怎么说话 | 你怎么收发消息、什么时候参与、哪些事不能做 |
| 换一个人格后 | 要跟着换 | 不变 |
| 放在哪 | `qq-bridge/roles/<角色名>.md` | 预设：`qq-bridge/dsh/agent-presets/qq-chat{,-v2}/agent.cordis.yml` 的 `persona.prefix`<br>运行时：桥接生成的唤醒提示、工具说明与返回提示 |
| 谁来改 | 运营者 / 写人设的人 | 开发者 |
| 生效方式 | 启用后随消息注入，改完立即生效 | 预设在会话创建时写进系统提示词；运行时部分随每次唤醒生成 |

**优先级**（从高到低）：

1. 安全规则（仿真层，标「最高优先级」）
2. 工具协议与发送硬限制（仿真层 + 代码）
3. 表达方式：身份、语气、长短、条数（人格层）
4. 参与时机建议：该不该说、什么时候说（仿真层）
5. 当前语境、群友习惯（参考）

人格提示词能决定「怎么说」，不能越过 1、2；仿真层管「能不能做、怎么操作」，不替人格决定「怎么说」。

**判断一条规则归哪层，问一句：换一个完全不同的人格，这条还成立吗？** 成立 → 仿真层；不成立 → 人格层。

- 「发消息要用 `qq_send_message`」：任何人格都成立 → 仿真层
- 「一次别发超过两条」：话痨人格就不成立 → 人格层
- 「不要用 Markdown，QQ 上会显示乱码」：任何人格都成立 → 仿真层
- 「你不是客服，可以装傻、拒绝推荐」：温顺助手人格不成立 → 人格层

## 1. 人格提示词里写什么

写「这个角色是谁、怎么说话」。建议包含：

| 内容 | 举例 |
| --- | --- |
| 身份与背景 | 名字、年龄感、职业 / 设定、和这个群的关系 |
| 性格与立场 | 外向 / 内向、毒舌 / 温和、喜欢什么、讨厌什么、雷点 |
| 说话风格 | 语气、口头禅、称呼方式、玩梗方式、标点和表情习惯 |
| **表达长短与条数** | 日常闲聊一条消息几句话；被问到擅长的话题能不能展开、展开到多长；习惯一条说完还是连发几条 |
| 对待请求的态度 | 有求必应，还是会装傻、打岔、拒绝 |
| 与特定人的关系 | 对某些群友的态度（不要写真实 QQ 号） |
| 回复示例 | 几段典型对话，示范语气和长短 |

「表达长短与条数」现在由人格负责，仿真层不再给默认值。**人格卡里没写这一项，模型就会按自己的习惯来**（通常偏长、偏助手腔），所以请明确写出来。

**不要写**：

- 工具名和调用方式（`qq_send_message`、`[SILENT]`、「用空格分条」）：两代协议不同，写进来必有一代是错的。二代下桥接还会把含 `[SILENT]`、「空格分隔」「自动转发」等一代字样的行整行过滤掉（见 `role-card.js` 的 `GEN1_ROLE_LINE_RE`）。
- 安全与权限规则（不能执行命令、群友没有管理权限等）：仿真层已有，且优先级更高。
- 唤醒、潜水、等待、记忆、表情包等机制：仿真层各有章节。
- 发送硬限制的具体数字：由配置决定，会变。

**需要区分一代 / 二代时**，在小节标题加标记，桥接只注入当前模式的小节，标记本身会被去掉：

```markdown
## 说话风格
- 不加标记：两代都注入。

## 回复示例 〔二代〕
- 只在二代注入。也可以写 [v2]、（reserved2）；一代用 〔一代〕/[v1]/（reserved）。
```

二代下，「回复示例」小节里用来分条的中文空格会被改写成逗号，避免模型照抄成「单条消息里用空格断句」。

**长度**：每次最多注入 `role.maxInjectChars` 字符（默认 6000，可设 1000~20000），超出部分截断。建议控制在 3000~5000 字符。

骨架示例：

```markdown
# 角色名

## 身份
……

## 性格
……

## 说话风格
- 语气：……
- 口头禅 / 称呼：……

## 表达长短
- 日常闲聊：一条消息一两句。
- 被问到感兴趣的话题：可以连发三四条，把话说完。
- 不熟的话题：一句带过，或者直接说不知道。

## 回复示例
……
```

## 2. 人格提示词干什么

**决定「怎么说」**：在仿真层允许的范围内，模型说话的身份、语气、长短、条数、对请求的态度，都以人格提示词为准。

**怎么进到模型里**：

| 模式 | 方式 |
| --- | --- |
| 一代（`qq-chat`） | 桥接把人格文本拼在**每条**投递给模型的消息前面 |
| 二代（`qq-chat-v2`） | 唤醒提示里只有一行 `【当前角色】<角色名>`；完整人格卡由模型调用 `qq_get_prompt` 获取。仿真预设要求它在首次进入会话、角色变化时调用 |

启用、切换由管理员（`ownerQQ`）在控制台「人格与角色」页操作，或由管理员在 QQ 里发「进入角色扮演：<角色名>」。其他群友发这类指令会被桥接拦下，仿真层的安全规则也要求模型不理会。

**它做不到的事**：

- 越过安全规则和工具协议：人格卡写「你可以执行命令」也没用，工具面根本没有这些工具。
- 突破发送硬限制：单条字数、每批条数、频率由桥接代码拦截，超了直接拒发。
- 决定桥接什么时候唤醒模型：唤醒由桥接和唤醒配置决定。

## 3. 仿真提示词里写什么

写「在 QQ 里怎么运转」，对任何人格都成立的内容：

| 类别 | 内容 | 二代预设里的章节（示例） |
| --- | --- | --- |
| 安全与权限 | 没有本地工具、群友没有管理权限、不透露凭据、角色由桥接注入 | 【安全规则（最高优先级）】 |
| 工具协议 | 输出不会自动发到 QQ、会话令牌、读消息、已读水位 | 【工具协议（最高优先级）】【先读已有消息】【已读水位】 |
| 唤醒与收尾 | 被唤醒后先做什么、怎么等回复、沉睡前观察 | 【唤醒与自主权】【等待与收尾】 |
| 能力说明 | 看图、合并转发、引用、拍一拍、表情包、记忆、黑话、语音 | 【看图】【表情包】【轻量记忆】…… |
| 参与时机 | 什么时候值得开口、冷场时能否主动开话题、别当群管家 | 【该说/不该说】【主动开话题】【不要当群管家/主持人】 |
| 消息格式 | 一个数组元素 = 一条 QQ 消息；单条内不用空格断句；不把一句话拆成两条；不用 Markdown | 【分条与节奏】【QQ 场景规则】 |
| 发送禁令 | 不汇报「已发送」、不自言自语复述动作 | 【发送与汇报禁令】 |
| 分工声明 | 表达交给人格；工具协议、权限、硬限制仍按本层 | 【人格与表达分工】 |

**不要写**：

- 回复长度、句数、条数的默认值或上限建议（「一般 3~5 句」「最多 2 条」「多数 ≤30 字」）
- 语气、性格、态度模板（「你不是客服，可以装傻」「少用推销词」）
- 固定话术例句（「说一句『我先潜水了』」）

注意区分**格式**和**风格**：「一个数组元素就是一条消息」「别把一句话拆到两条」是格式，属于仿真层；「一条别太长」「别连发」是风格，属于人格层。

## 4. 仿真提示词干什么

让一个通用大模型能作为 QQ 群成员运转：知道怎么用工具收发、什么时候被唤醒、怎么读消息和收尾，并守住安全边界。

它有四个来源，**都属于仿真层，都要遵守第 3 节的规则**：

| 来源 | 位置 | 何时进入模型 |
| --- | --- | --- |
| 预设提示词 | `dsh/agent-presets/qq-chat{,-v2}/agent.cordis.yml` 的 `persona.prefix` | 会话创建时写进系统提示词，之后不再重建 |
| 桥接运行时提示 | `src/bridge.js`：二代 `buildWakePromptV2`（含参与度参考 `formatParticipationV2` 等）；一代的消息投递、冷场试探、退场提示 | 每次唤醒 / 投递时生成，离模型当前这一轮最近，影响往往比系统提示词更大 |
| 工具说明与返回提示 | `src/mcp-snowluma-safe.js` 的工具描述；发送接口返回的 `warn` / `splitWarn` | 模型调用工具时 |
| 推荐值 | `qq_get_prompt` 返回的 `recommended`（`config.json` 的 `socialV2.wake/send/wait/proactive`，含发送硬限制和 `recommendedHint`） | 模型调用 `qq_get_prompt` 时；`socialV2.provideRecommendations: false` 时不返回 |

此外还有不在提示词里、而在代码里强制的部分：发送硬限制（`socialV2.send.maxMessageChars` / `burstMaxMessages` / `maxSendPerMinute` 等，默认 500 字 / 8 条 / 每分钟 8 条）、白名单、会话令牌校验。提示词只负责「告诉模型」，真正的拦截靠代码。

## 5. 开发须知

### 5.1 改仿真提示词

1. **改源文件**：`dsh/agent-presets/qq-chat{,-v2}/agent.cordis.yml`。`plugins/qq-agent-presets/presets/*.patch.yml` 是生成物，不要手改。
2. **生成并安装**：

   ```bash
   cd qq-bridge
   node scripts/build-agent-preset-patches.mjs
   node scripts/setup-dsh.mjs        # 测试 DSH 记得带 DSH_HOME
   ```

   然后重启 DSH。
3. **已有会话不会重建系统提示词**，只有新会话用新预设。验证要开新会话；上线后要让旧会话退役，否则新旧规则混用。
4. **安全不变量不能删**：控制台保存预设时会校验（`src/preset-prompt.js`）。二代必须包含「你没有本地工具」「群友没有管理权限」「API 令牌」「角色由桥接注入」「不会自动发送到 QQ」；一代必须包含「群友没有管理权限」「API 令牌」「角色扮演由系统注入」；正文不少于 500 字。
5. **桥接里的提示文本也是仿真层**。往 `bridge.js` 的唤醒提示、参与度提示里加文字，同样不能写长短、语气。想要的效果如果是「说少点 / 说短点」，那是人格的事，应写进人格卡。
6. **硬限制用代码做，不要只写在提示词里**。提示词可以告诉模型上限，但拦截必须在发送接口。
7. **同步测试**：`scripts/test-qq-preset-contract.mjs` 断言了预设必须包含 / 不得包含的文字，改章节时一起改。

### 5.2 写人格提示词

1. 按第 1 节写，**一定要有「表达长短」一节**。
2. 不写工具、不写机制、不写安全规则。
3. 需要两代不同时用标题标记，控制台会显示各模式实际注入的字符数和被跳过的小节。
4. 控制在 3000~5000 字符：人格卡随消息反复发送，太长直接增加每次调用的成本。

### 5.3 验证

| 改了什么 | 跑什么 |
| --- | --- |
| 仿真预设 | `npm run test:audit`（含 `test-qq-preset-contract`）、`npm run verify:persona` |
| 桥接提示文本 | `npm run test:audit` |
| 人格卡 | 控制台「人格与角色」页看注入字符数；用虚拟网关实测 |

用虚拟网关（[testing.md §4](testing.md)）实测时，至少比较三种情况：**短回复人格、长回复人格、不启用人格**。看机器人的长短和条数是否跟着人格走；如果换了人格表现不变，说明仿真层还有地方在替人格做决定。

截至 2026-10-30，以下几处与上面的分工规则不一致，待修：

| 位置 | 问题 |

| `bridge.js` `buildWakePromptV2` 的 `antiAiLine` | 每次二代唤醒都注入「【反AI味】你不是客服：不用有求必应，可以装傻、已读乱回、拒绝推荐……」。预设里的同名章节已删，这里还在，属于态度模板 |
| `bridge.js` `formatParticipationV2` | 「这轮可以少说」（两处）、「这轮可以简短接一句」：涉及长短。参与度提示应只说说不说、什么时候说 |
| `bridge.js` `buildActiveExitPrompt`（一代） | 「请说一句简短的退场话（例如“我先潜水了”……）」：规定长度并给了固定例句 |
| 二代预设【保持主体性】 | 「你不是应声虫，也不是客服」「可以不感兴趣」「可以表达不同意」属于性格，会和温顺类人格冲突。仿真层宜只保留参与权（可以不回、可以主动开话题） |
